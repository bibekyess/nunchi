# 10 — The UI layer

The UI is React components styled with Tailwind. This chapter is a map of the components
and the techniques they use for performance, layout and accessibility. You don't need it to
understand the speech pipeline, but it explains a lot of small decisions you'll see in
`components/`.

---

## Part 1: Pages and component tree

```
app/layout.tsx                     <html>, theme script, font preloads
├── app/page.tsx  (/)              Server Component: static layout, client parts inside
│   ├── Logo, HealthDot, ProcessingButton, ThemeToggle      header
│   ├── UnlockCard                 passcode entry when the server is locked
│   ├── NewSessionButton           router.push(`/session/${crypto.randomUUID()}`)
│   └── RecentSessions             list from IndexedDB, grouped Today / This week / Earlier
│
└── app/session/[id]/page.tsx      <Suspense> + SessionView
    └── SessionControllerProvider  loads session, creates controller (chapter 09)
        └── SessionLayout

            ├── panel: TranscriptList → UtteranceBlock × N
            ├── panel: SummaryPanel
            ├── RecordBar          the floating dock: status, mic button, stop
            └── MicErrorScreen     full-screen help when the mic fails
```

Folders in `components/`:

| Folder        | Contents                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui/`         | small primitives: `Button`, `IconButton`, `Dialog` (native `<dialog>`), `Menu`, `SegmentedControl`, `Badge`, `Card`, fields. No component library |
| `controls/`   | dialogs and menus: Processing, Audio settings, Glossary, language menu, view filter, display buttons, record bar                                  |
| `session/`    | session page structure: view, header, menu, banners, controller context, mic errors                                                               |
| `transcript/` | the line list and one line                                                                                                                        |
| `summary/`    | the summary tab                                                                                                                                   |
| `home/`       | home page pieces                                                                                                                                  |

**Why no component library?** DECISIONS.md Phase 0 and Phase 1: shadcn/ui's registry was
blocked from the build environment, so a few local primitives were written instead. They've
stayed small. Native elements are used where they're best: `<dialog>` for modals and
`<select>` for the language menu (_"the best picker on phones"_).

## Part 2: Rendering performance

A live transcript is a hard case for React: hundreds of lines, with one of them changing 20+
times a second. The techniques:

1. **Each line selects only its own data.** `UtteranceBlock` calls
   `useSessionStore((s) => s.byId[id])` and is wrapped in `memo` (`UtteranceBlock.tsx:77`).
   When line 42's translation grows, only line 42 re-renders (chapter 09, normalized state).
2. **Fast-changing values in tiny components.** The mic level changes ~30 times a second. Only
   `MicLevelRing` and `LevelMeter` subscribe to it (`components/controls/RecordBar.tsx:8`), so
   the rest of the dock doesn't re-render.
3. **CSS variables instead of state for layout.** The top bar's height changes when a banner
   appears. A `ResizeObserver` writes it straight to the `--top-inset` CSS variable
   (`components/session/SessionView.tsx:73`): _"so a resize never re-renders the transcript."_
4. **Both tabs stay mounted.** Transcript and Summary are hidden with CSS, not unmounted
   (`SessionView.tsx:110`), so the transcript keeps its scroll position and a summary keeps
   streaming while you look at the other tab (DECISIONS.md Phase 3).
5. **Animations only for new lines.** When a saved session with 500 lines opens, they appear
   instantly. Only lines added while you watch slide in (`initialIds` in
   `TranscriptList.tsx:32`). The animation class is removed when it ends, because hiding and
   showing the tab would restart CSS animations (comment, `UtteranceBlock.tsx:72`).

## Part 3: Auto-scroll that respects the reader

`TranscriptList` (`components/transcript/TranscriptList.tsx:16`) follows new lines **only if
you're already at the bottom** (within 80 px). Scroll up to re-read something and it stops
following, and a "Latest" button appears. The scroll check runs in `useLayoutEffect`, before
the browser paints, so there's no visible jump. A `ResizeObserver` keeps following when the
phone keyboard opens or the screen rotates.

## Part 4: Displaying two languages

The display options (`lib/display/`) are **per device** and persisted:

- **View filter by language, not by role** (`visibleParts`, `lib/display/view.ts:26`). Picking
  "English" shows English speakers' originals _and_ Korean speakers' translations, so it reads
  as one English transcript. DECISIONS.md Phase 2 says this matches the "Cuckoo" app the
  design follows, and it replaced the plan's "Original / Translation" toggle. Lines still being
  transcribed (language unknown) stay visible.
- **Side by side = one column per language** (한국어 left, English right), not "original |
  translation", so each column stays one language when speakers alternate. Only on screens
  ≥ 768 px.
- **Text size** cycles S → M → L with one tap.

## Part 5: Placeholders and feedback

- A line being transcribed shows **shimmer bars whose width grows with the clip's duration**
  (`placeholderWidth`, `UtteranceBlock.tsx:13`), a hint of how much was said.
- A translating line shows a blinking **caret**.
- The status text in the dock changes: "Starting microphone…", "Listening", "Hearing speech…",
  "Paused".
- **Banners** (`components/session/Banners.tsx`) for: offline (only if a chosen engine needs
  the network), saving problems, interruption (clears itself after 8 s), tab sharing stopped
  (with "Share again"), passcode needed (inline field), failed lines (with "Retry all").
- **The health badge** (`components/HealthDot.tsx`) summarizes engine statuses in a few words.
  If the _only_ problem is the missing passcode it says "Server locked" once, instead of three
  scary "down" labels (commit `32a3ca1`).

## Part 6: Accessibility details

Worth noticing, because they're easy to forget:

- The transcript is an `aria-live="polite"` region, so screen readers announce new lines.
- The dock's status is `role="status"`, and banners are `role="alert"`.
- The big mic button in the empty state is `aria-hidden` and `tabIndex={-1}`. It's a pointer
  shortcut only, so keyboard and screen-reader users get exactly one "Start listening" button,
  the dock's (comment, `TranscriptList.tsx:157`).
- The hover-only copy button is kept out of the tab order. Tapping a line reveals a real,
  focusable copy button instead.
- Each text element has `lang={u.sourceLang}`, so screen readers pronounce Korean as Korean.
- Tabs use `role="tablist"` / `tabpanel` with `aria-controls` and `aria-labelledby`.

## Part 7: Theme without a flash

`app/layout.tsx:39` injects a tiny inline script (`THEME_INIT_SCRIPT`,
`lib/browser/theme-script.ts:21`) that runs **before the first paint**: it reads the saved theme
(or the OS preference) and sets `data-theme` on `<html>`. Without it, a dark-mode user would
see a white flash on every load, because React only runs after the page is painted. The
script is plain ES5 and self-contained, because it runs before any bundle loads.
`suppressHydrationWarning` on `<html>` tells React that the attribute is _expected_ to differ
from the server's HTML.

Colors are **design tokens** (`--ink`, `--surface`, `--lavender`, …) in `app/globals.css`, with
light and dark values, so components never hard-code colors.

## Try it

1. Install the React DevTools extension, enable "Highlight updates when components render",
   and watch a session while a translation streams. Only one line (and the meter) should flash.
2. Scroll up in a long transcript while speaking. Watch the "Latest" button appear, and find
   `STICK_THRESHOLD`.
3. Switch the view filter to English and work out, using `visibleParts`, which parts of a
   Korean line and an English line are shown.
4. Turn on a screen reader (VoiceOver: Cmd+F5 on macOS) and listen to new lines being
   announced.
